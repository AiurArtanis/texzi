## 结论与基线

按设计包 v1.0 的 T00–T18 实施，先证明文档内核和 Markdown 保真，再扩展完整工作台。此任务单不是产品已实现或已验收的声明。

- 仓库： https://github.com/AiurArtanis/texzi ，私有；目标本地目录 `D:\Work\texzi`。
- 原始设计：`C:\Users\eehyk\Downloads\Cindy Downloads\texzi-design-v1`。保留原件，导入副本时核对 manifest。
- Rust + NSH Windows 原生；NSH 固定 `224d9a795c7ac9d10d75750de9351adac5549675`（设计声明 v0.5.1）。实施者必须实际获取并核验源码、工具链、features 和许可，不能仅照抄版本号宣称构建通过。
- Windows x64；Windows 10 22H2 主测，1809 兼容性另列。Windows 11 不得因开发机可运行就宣称全矩阵通过。
- 单一 DocumentStore/历史；每 View 独立模式、选区、滚动；原文为唯一事实源。模式切换 0 文本事务、0 undo 增量、dirty 不变。
- 保留全部 P0。不得用 WebView/只读预览替代原生 WYSIWYG，不引入 IDE、插件市场、云同步。

## 设计审读发现

1. `DECISIONS.md` 冷启动说明写“按 p95 判定”，与 `PERFORMANCE_PLAN.md` 的每轮有效测量 ≤2 秒矛盾。按 README 指定的性能权威文件执行后者；在导入副本修正并记录依据，不改原件。
2. `DECISIONS.md` 的 R04/R06/R10 Gate 归属与 HANDOFF 不一致。IME/UIA 归 G4，保存可靠性归 G3；保留任务与 AC 映射，避免因编号漂移漏验。
3. NSH 的增量适配、RichEditor 保真/虚拟化属于待验证风险。当前依据是设计包的源码审读记录；本轮尚未独立验证上游实现或运行原生客户端。

## 首轮可执行任务

### TX-00 / Cozy：T00 构建基线

范围：导入完整设计副本和校验清单；固定 Rust/NSH/features；建立最小 Rust workspace、Cargo.lock、构建说明、许可清单和最小原生窗口。建立设计勘误记录。不得覆盖原始设计或已有未跟踪文件。

交付：直接在 main 小步提交并推送的候选 commit、Release 程序 hash、实际构建命令、环境版本和日志。初版私有开发无需 PR；推送前检查远端并发变更。禁止将空窗口称为编辑器完成。没有 Windows 10 测试环境时明确 BLOCKED/NOT_RUN，不能以 Windows 11 替代 G0。

验收：干净 checkout 按说明可构建；实际原生窗口启动/关闭；依赖版本与 feature 可追溯；失败后可退出且无残留用户文档写入。G0 的完整条件按 HANDOFF，不因最小窗口通过就放过未锁定依赖。

### TX-01 / Cozy，Rusty 评审：T01 契约

TX-00 基线后定义 DocId/ViewId/Revision、UTF-8/UTF-16/grapheme 坐标、EOL/provenance、事务与事件、唯一 history、saved token、异步保存状态机。先交可评审契约与行为示例，再扩展实现。

必须覆盖：两窗口共享正文但位置独立；跨模式 undo；保存 revision N 时继续编辑 N+1，保存完成不清除 N+1 的 dirty；undo 回保存状态；过期异步结果被拒绝；失效事务无部分提交。

### TX-02 / Steamy：验证准备及首候选复验

可先并行只读审阅 `ACCEPTANCE.md`、`HANDOFF.md`、`PERFORMANCE_PLAN.md`，核对设计 manifest，登记可用 Windows/IME/DPI 环境，建立 FR→AC→候选→证据映射。112 条产品验收及 16 项 TP 初始为 NOT_RUN，设计包旧结果不得当成本次结果。

拿到 TX-00 候选后，固定 commit、工作区状态、程序 hash，独立 checkout/构建，先启动冒烟再最小复现。性能追踪实施属于 T02，待 T01 接口固定；Steamy 不自行修改产品或修正测试实现，发现测试错误先报。

输出仅用 PASS / FAIL / PARTIAL / BLOCKED / NOT_RUN；记录命令、退出码、OS/工具链、覆盖范围、证据路径。明确区分静态检查、组件测试、真实应用运行、人工验收。构建成功只支持构建结论。

## 失败、回退与证据

- 每个候选只覆盖一个明确目标，固定 commit 或文件 hash。FAIL 交回 Cozy 修复并生成新候选；Steamy 复验受影响范围并保留历史失败。
- Rusty 评审接口、影响面、失败路径和回退方式；不以改 UI 或降低目标掩盖内核缺陷。
- 故障注入仅操作生成 fixture；不改用户文档，不自动重启用户机器。存储格式变更必须有版本与旧数据读取/迁移策略。
- 开发候选保留前一可运行版本；回退使用新提交/独立 checkout，不 reset/clean 用户工作区。
- 性能按模式和样本分开，保留 p50/p95/p99/max、失败率及输入→revision→present 证据；原型耗时不计入原生性能。
- Cozy 五行交付：改了什么 / 为什么 / 怎么验证 / 候选标识 / 没把握的点。
- 群内只回任务单、候选和验证结论，长日志引用路径。初版允许直接提交并推送 main；公开与正式发行另行处理。当前流程以仓库根目录 CONTRIBUTING.md 为准。
