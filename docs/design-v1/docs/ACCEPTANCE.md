# texzi 可执行验收清单

版本：1.0　日期：2026-11-15　状态：**设计验收计划，尚未执行原生验收**

本文包含 112 条带前提、操作和预期结果的测试。目标是 Windows 原生 NSH Release 构建；浏览器原型可帮助核对布局和流程，但不能给原生 IME、文件操作、共享缓冲、恢复或性能用例签“通过”。

## 1. 执行与取证规则

### 1.1 环境记录

每轮填写：构建 commit、NSH commit、依赖锁文件摘要、系统版本/build、x64、CPU、RAM、磁盘、显卡/驱动、屏幕刷新率、DPI、输入法名称/版本、字体可用性、Defender 状态及测试日期。支持承诺中的最低 Windows build 与主力 Windows 10/11 环境分别执行；不得把 Windows 11 结果替代 Windows 10。

数值门槛、原生埋点和样本数使用 [PERFORMANCE_PLAN.md](PERFORMANCE_PLAN.md)。已经接受的目标与后续建议阈值在该文档中区分；验收报告必须注明所用模式。源码表现达标不能冒充同规模所见即所得达标。

### 1.2 结果格式

每例记录 `用例ID / Pass|Fail|Blocked|NotRun / 环境 / 操作证据 / 实际结果 / 缺陷链接`。所有用例初始为 NotRun。涉及内容正确性的例子保存输入/预期/实际文件和 SHA-256；涉及动画/IME 用录屏与事件时间线；涉及性能保留原始数据，不只留一张均值图。

P0 内容损坏、无法恢复、异常覆盖、IME 丢字、多视图错误、不可用的所见即所得均阻断发布。视觉细节可按缺陷等级处理，但不能把功能缺失列为“美观优化”。若某场景因系统权限不可复现，标 Blocked 并说明，不计通过。

### 1.3 建议测试方法

- 文件正确性：保存前后 `Get-FileHash -Algorithm SHA256`；局部编辑用字节 diff 校验未改区域。
- UI：Windows UI Automation 驱动菜单、焦点、设置与文档操作；IME 场景使用真实系统输入法，至少一轮人工复核。
- 文件异常：测试目录独立于真实工作资料；用受控文件锁、只读属性、不可写目录、磁盘配额/虚拟盘和可取消 I/O 进行故障注入。
- 恢复：测试构建提供恢复日志故障注入及修订水位输出；禁止只用正常退出模拟崩溃。
- 大文件：固定生成器与 seed，文档大小、行结构、编码和最长行进入报告；不拿随机样本掩盖长行开销。

## 2. 固定样例与预期口径

以下样例必须生成在独立测试目录，所有用例从干净副本开始，除非前提要求沿用同一会话。

| Fixture | 内容/结构 | 用途 |
|---|---|---|
| F01-plain | UTF-8 无 BOM、CRLF：`alpha alphabet Alpha alpha_1`；下一行 `猫咪 猫咪们 猫`；再下一行 `A😀é👩🏽‍💻🇨🇳B`；含 Tab、空行及末行无换行 | 搜索、Unicode、行编辑 |
| F02-markdown | H1/H2、Setext、粗斜删除线、引用、嵌套列表、`- [ ]`/`- [x]`、带对齐的管道表格、围栏代码、引用式链接与定义、图片、空行、行尾双空格 | 所见即所得与原文保真 |
| F03-raw-md | 在 F02 加原始 HTML、数学、Mermaid、脚注、未知容器、未闭合围栏；保留原 `*`/`_`、缩进和多个空行 | 不支持语法保留 |
| F04-enc | 同一有限字符文本分别保存 UTF-8、UTF-8 BOM、UTF-16 LE/BE、GBK；GB18030 另含 `𠀀`；Windows-1252 使用 `café €` | 编解码往返与不可表示字符 |
| F05-mixed | 字节序列对应 `one\r\ntwo\nthree\rfour`；末行无换行 | 混合换行 |
| F06-code | 各目标语言最小有效片段，含中文注释与字符串；JSON 至少两层结构 | 语法高亮与降级 |
| F07-workspace | 根目录 A/B，各有同名 `notes.txt`；另有目录外独立文件；权限受限子目录、`.git`、`node_modules`、符号链接环路 | 工作区与搜索 |
| F08-size | 1/10/100 MiB 普通文本及 Markdown 源码；1 GiB 探索样例；单行 1/10 MiB 样例 | 性能与长行 |
| F09-invalid | 非法 UTF-8 字节 `C3 28`，二进制样例，截断 UTF-16 及包含 NUL 的有效 UTF-16 | 错误分类 |
| F10-rich-scale | 长 Markdown、超过建议复杂度的块数、单表大规模单元格、延迟加载图片 | 富编辑增量与锚点 |

F01 中不区分大小写的子串 `alpha` 有 **4** 个匹配；按字母/数字/下划线构成词的全字规则有 **2** 个匹配。`猫` 的子串有 **3** 个匹配，按连续汉字不分词的全字规则只有独立 `猫` **1** 个。字素样例必须按实际组合字符生成，`é` 是 `e + U+0301`，不能替换为预组字符 `é`。

F02 建议至少包含以下原文，另加图片与原样节点后保存基线 SHA-256：

```markdown
# texzi · 产品笔记

本周计划
--------

- [x] 核对功能边界
- [ ] 确认概念设计
  - 子项保留两个空格

**直接编辑**排版后的正文，随时切换源码。

| 模式 | 用途 |
|:----|----:|
| 所见即所得 | 直接写作 |
| 源码 | 精确修改 Markdown |

[参考][doc]

[doc]: https://example.com "标题"
```

## 10. 发布判断与交接

### 10.1 必须通过的组合场景

单个组件通过不够，以下组合至少完整走一轮：

1. **中文写作闭环：** 新建 Markdown → 所见即所得输入中文 → 任务框 → 表格 → 代码块 → 切源码 → 正则替换 → 跨模式撤销 → 保存 → 重开字节检查。
2. **多视图闭环：** 同文档两模式分屏 → 另窗移动一个视图 → 交替编辑 → 外部变化冲突 → 另存副本 → 关闭一窗 → 强杀另一窗 → 恢复。
3. **旧编码闭环：** 手动打开 GB18030 → 中文输入 → 多光标 → 增加不可被 GBK 表示字符 → 保存失败可解释 → UTF-8另存 → 原文件仍完整。
4. **大文件闭环：** 100MiB源码 → 搜索 → 取消 → 批量替换准备 → 另一视图编辑导致revision变化 → 正确重算 → 一步撤销 → 保存/内存核查。
5. **异常闭环：** dirty临时文本与磁盘文件 → 恢复落盘失败 → 取消退出 → 恢复后再次退出 → 强杀 → 部分损坏记录恢复 → 磁盘冲突处理。

### 10.2 不允许替代的证据

- 不以“NSH 文档写支持”替代 AC-030–034 中文输入结果。
- 不以“支持 Markdown 展示”替代 AC-048 的直接编辑。
- 不以截图看起来一致替代 AC-049/050 的原字节/局部 patch 检查。
- 不以多个独立文本控件同步字符串替代 AC-013/064/065 的共享历史。
- 不以正常退出再打开替代 AC-086/087 的异常恢复。
- 不以浏览器帧率或硬件不同的平均数替代原生性能计划。

### 10.3 与技术任务的连接

每个实施任务在 [HANDOFF.md](HANDOFF.md) 关联至少一个上述 AC 编号。原生能力闸门、编辑模型、WYSIWYG 源映射、Windows输入、多窗口、搜索、编码恢复和性能分别由技术方案的 Gate/TP 记录实现证据。出现设计建议值需要调整时，同步 PRD、UI_SPEC、SETTINGS/COMMANDS 数据和本清单，不让同一行为在不同文档出现两个默认。

所有测试结果由执行团队补填；本交接稿没有将任何未运行的原生测试标为通过。
