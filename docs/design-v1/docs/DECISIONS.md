## 2. 已接受的性能目标

| 项目 | 已接受的目标值 | 适用说明 |
|---|---|---|
| 热启动 | p95 ≤800 ms | 从启动请求到首个可输入编辑视图；样本与测量见性能计划 |
| 冷启动 | ≤2 s | 重启后的受控冷启动样本；计划按 p95 判定并保留全部结果 |
| 常规 1–10 MiB 输入 | p95 ≤33 ms、p99 ≤50 ms | 应用收到正式输入/IME commit 到对应 revision 的 present |
| 60 Hz 滚动 | p95 帧间隔 ≤20 ms | 测实际连续滚动；p99 与掉帧等额外观测见计划 |
| 100 MiB 普通文本首屏 | ≤2 s | 已运行应用打开；真实正文出现，不以加载提示计 |
| 100 MiB 普通文本可编辑 | ≤5 s | 全文模型能够正确编辑、撤销、搜索与保存 |

测试环境仍是**建议参考环境**：Core i5-12400、16 GiB、NVMe/NTFS、集显、1080p 60 Hz、Win10 22H2 x64、Release。它不是用户电脑资料，也不表示用户逐项确认了硬件。1/10 MiB 普通 Markdown WYSIWYG 延用输入/滚动目标是设计展开，需与源码分别测；100 MiB 目标不扩展为任意复杂 WYSIWYG 承诺。[完整口径](PERFORMANCE_PLAN.md)

## 3. 本方案选择，未冒充用户逐项指定

| 决策 | 选择及理由 | 可调整边界 |
|---|---|---|
| D01 原生技术路线 | Rust + NSH Windows 后端；核心编辑不依赖 WebView | 不能暗改成 Electron/纯 Web 产品；原型允许浏览器实现以审阅 |
| D02 固定上游 | NSH v0.5.1 固定 commit；VS Code 1.146.0 固定快捷键参照 | 实施若升级需差异审查与测试，不跟随 main 漂移 |
| D03 Win10 小版本 | 建议 1809 为工程最低版本，22H2 为主测环境 | 依据 NSH 文档，不等于已测过；若 1809 失败先给明确原因 |
| D04 唯一文档模型 | 原文 + EOL/provenance 元数据 + 唯一历史；视图独立 | 不能以整篇 RichEditor 导出重新覆盖原文 |
| D05 Markdown 支持层 | CommonMark/GFM 基础、标题/列表/表格/代码等；不支持结构保留原文 | 公式、图表、任意 HTML 不自动加入 P0；保留用户文本 |
| D06 查找语义 | WYSIWYG 普通查找作用于正文；正则/替换切源码并重算计数 | 不允许同一个计数混合两个范围或悄悄替换源码隐藏部分 |
| D07 多光标 | 第一版以源码多光标为完整路径；WYSIWYG 调用先转源码 | 保留位置并说明模式变化；不假称富文本复杂多选已原生具备 |
| D08 搜索实现 | 字面检索线性扫描；PCRE2 UTF/UCP 在可取消 worker | 锁定具体库版本后验收；与 VS Code/浏览器正则不声称完全一致 |
| D09 设置默认 | 系统主题、UI14、源码16×1.5、Markdown16×1.7、UTF-8/CRLF、新文件自动保存关、恢复开 | 各项均在 SETTINGS 中标状态；已有文件保留编码/EOL |
| D10 文件夹默认 | 打开文件在当前窗口；打开文件夹默认新窗口 | 替换当前根树仍保留已打开文档，用户可在设置改默认 |
| D11 工作台上限 | 建议最多8组、组最小240×160 DIP | 依据可用空间禁用无效拆分；原型3组只是演示限制 |
| D12 大文件策略 | 达到20 MiB启用渐进优化；达到200 MiB先估资源；长行阈值20,000 Unicode scalar | 全是工程建议；20 MiB不等于只读或拒绝打开 |
| D13 恢复策略 | 默认1s刷盘、默认配置下建议可恢复损失窗口≤2s | 是新增工程预算，待故障注入证明；不是断电零丢失保证 |
| D14 快捷键冲突 | WYSIWYG正文Ctrl+B加粗；其他上下文Ctrl+B侧栏；Ctrl+K Ctrl+B通用侧栏 | 保留IME优先级、系统保留键；完整冲突表见COMMANDS |
| D15 原型存储 | 浏览器本地会话、导入UTF-8和下载副本 | 只为审阅；不是原生保存/恢复实现 |

完整默认值不在此重复维护。SETTINGS 的 63 项、COMMANDS 的 115 项是参数权威表。

## 5. 参考产品的边界

VS Code 用来对照编辑与窗口习惯；texzi自行明确了每项支持范围，不复制IDE、扩展系统或全部配置。快捷键参照版本固定在1.146.0，源码核实和Windows真机按键验收是两种证据。

quiet.md 的 Rust+GPUI 原生富编辑和本地Markdown工作方式有参考价值，但它不是可直接挂到NSH的现成控件；其文档模型、Markdown写回与平台渲染需要适配。其官方性能数据来自另一台macOS设备，不能用来替代texzi Windows性能。[来源与限制](SOURCES.md)

## 6. 仅作建议的架构预留

保留内部 CommandRegistry、语法高亮提供器接口、文件编解码接口和版本化配置schema，便于替换内置实现与做测试。首版不实现动态加载、第三方代码执行、插件SDK、扩展权限、扩展市场、主题脚本或用户脚本。

文档/视图ID、事务版本和恢复格式的版本字段属于当前可靠性需要，不以“未来可扩展”为由额外建立插件平台。公开API兼容性承诺留到有真实扩展需求之后。
