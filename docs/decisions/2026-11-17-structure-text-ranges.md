# 已知结构的文本范围与换行身份

状态：实施候选，尚待新 CI 与同包本机 GUI，不继承旧程序运行结论。

既有唯一 Store/history 不变。下一步先覆盖已知结构内部文本，避免修改一个列表项或表格单元格就重新序列化整个块，改写原符号、对齐短横线和空格。

1. 当整批已应用 Rich transaction 合计只有一个普通 ReplaceStep、slice 两端均闭合且只含 text 时，读取该 step 的 from/to，经严格源映射生成局部替换。完整重解析后的树必须与目标富树相同，才采用这个范围。否则回到现有保真结构路径，仍有不能表示的情况时原子拒绝。原富树完全不变时返回零正文事务，不能借重放一个相同 text step 增 revision/dirty/history。
2. 普通多步 transaction 仅一个文本叶变化、祖先及其余兄弟 markup/内容都不变时，递归定位该叶，并只替换已验证的原文唯一范围；不改表格 padding/对齐、列表符号及邻接 opaque 块。多叶/模糊映射不是本次完整支持承诺。
3. 已知围栏代码块用首行结束后的内容起点，且与节点的完整 text 严格相等，确定 code 内容源范围；不把同名语言标签误当正文。空代码块光标也映射到围栏内部。缩进/不连续原文未验证时不猜测。
4. 代码块插入 LF 使用实际 step 指定的插入点，原 LF/CRLF 保留原 provenance；新增 LF 继续依 Store 的主导 EOL 编码。不能用多个相同 LF 的 diff 猜测哪个是旧换行。没有足够 step 证据的多行结构修改继续保留限制。
5. 单一任务框 checked 属性变化，在其他树/属性不变且原 mdast 任务顺序/checked 状态一致时，只替换原任务标记中一个字符。保留原列表符号、其他任务的 X 大小写及 EOL；无法定位时拒绝，不猜测任务范围。

原规则保持：无修改切换零正文事务；未改源区间和未知语法保留；模式的失败/组合保护不变。图片属性/插入控制、嵌套结构 Enter/列表操作、空表格单元格映射、多选/scroll、CST增量/性能及完整T07继续按原任务实现，不能凭本次文本编辑候选声称首版完成。
