# 空任务项的派生投影

原 PRD 与固定设计不改。本决策修复 f66a7a0 本机独测的实际反例：`- [x] done\n` 行尾 Enter 被拒；先前有正文的中间拆分测试不覆盖新空任务项。

markdown1.0.0 的 GFM task 检查要求标记后有非空白正文。编辑器的新空任务项需要显示为未勾选框与空段，Source 明确保留 `- [ ] `，不添加不可见正文字符。对此仅增加派生投影规则：同级列表的各项均为已识别任务或精确、未转义、尾部只有空格/Tab的空任务标记时，绑定 AST item/paragraph 及原始位置识别空项。含普通项的同级列表不提升任务语义；转义或实体括号仍为原文字面。

一次性 importer 字符串可在这些明确位置加入私有标记，以调用现有 NSH importer；导入后必须按原 AST 空段身份、节点形状和数量移除。未支持容器或任一身份/数量不符时整个补充失败，回到完整原样及源码入口，不接受仍含导入标记的树，也不再以普通 importer 的假成功掩盖不匹配。真实同文字符不按全文搜索移除。Source、Store、来源与历史不写入导入标记，SourceMap继续绑定原坐标。

实际操作的确定预期：

1. `- [x] done\n` 行尾 Enter 得到 `- [x] done\n- [ ] \n`；旧 `[x]` 不变，新项 checked=false、正文为空。
2. 新项输入 `next`，再选择它并 Backspace，可回空任务项；Source 三次 Undo/Redo分别恢复输入/新增项/删除的原始 bytes、token、EOL与provenance，dirty与history按唯一Store变化。
3. 既有 `done` 叶和新空项光标均有严格映射。初导单空项可落到同块空段；模式切换本身0正文/历史增量。
4. 真实私有区字符、转义括号、混合普通项和不支持的引用容器有保留控制；不因此宣称完整混合/嵌套任务列表编辑已支持。
